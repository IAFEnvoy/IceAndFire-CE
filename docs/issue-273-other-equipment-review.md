# #273：26.1.2 其余装备模型代码检查

检查日期：2026-11-13。目标是 `master` 的 Minecraft 26.1.2，包括当前尚未提交的龙钢甲、海蛇甲预览修正。本次仅检查源码和资源、计算坐标，没有启动客户端，没有修改生产代码。

## 结论

没有发现其它附加立方体像修复前的龙钢面甲那样，整体落入基础盔甲外壳的几何范围内。但仍有相同根因造成的局部遮挡增加，其中三类龙鳞甲的下方腿刺最明显，值得继续调整。银甲裙片的余量也明显减少，属于次要候选。

“未整体落入外壳”不代表视觉完全正确；以下检查不验证最终贴图、光照、观察角度及运动姿态。反过来，龙角或鳍的根部嵌入外壳本身也是正常建模方式，不能把所有没有传入 `deformation` 的部件都当成错误。

## 范围和计算方法

从 `IafRenderers.registerArmorRenderers()` 和 `ScaleArmorRenderer.register()` 追踪实际渲染路径，覆盖全部 10 个自定义人形盔甲模型、160 个附加立方体，包括嵌套子部件：

| 模型 | 附加立方体数 | 结果 |
| --- | ---: | --- |
| 火龙钢甲 | 16 | 已纳入预览；未发现其它部件整体进入基础外壳 |
| 冰龙钢甲 | 20 | 同上 |
| 电龙钢甲 | 20 | 同上 |
| 火龙鳞甲 | 23 | 下方腿刺露出量很小；肩刺、背刺也有缩短 |
| 冰龙鳞甲 | 25 | 与火龙鳞甲共用相同的腿刺、肩刺、背刺参数 |
| 电龙鳞甲 | 27 | 与火龙鳞甲共用相同的腿刺、肩刺、背刺参数 |
| 海蛇甲 | 8 | 护肩已纳入预览；头鳍、臂鳍、腿鳍仍明显伸出 |
| 银甲 | 6 | 裙片余量变小；面罩局部侧面受覆盖，整体仍明显伸出 |
| 死亡蠕虫甲 | 11 | 尖刺根部覆盖增加，未发现整体吞没 |
| 巨魔甲 | 4 | 根部覆盖增加，角本体及后续分段仍伸出 |

`BasicArmorRenderer` 和 `ScaleArmorRenderer` 按装备槽裁切模型。`HUMANOID_LEGGINGS` 使用 `d=0.38`，头盔、胸甲、靴子使用 `d=0.45`。`HumanoidModel.createMesh()` 的 `hat` 另加 `0.5`，因此当前头盔最大外壳是 `x/z=±4.95`、`y=[-8.95,0.95]`。

对照值 `d=0` 指此前分析确认的原版 beta-2 外壳参数，并非将 beta-3 当作零膨胀版本。计算使用模型的 `addBox` 坐标、膨胀量和完整父子 `PartPose` 链，旋转顺序与目标版本 `ModelPart.translateAndRotate()` 的 `rotationZYX` 一致。坐标以所属头、身体或肢体为参考，单位为模型像素，1 模型像素为 1/16 方块。

分析脚本及完整坐标留在忽略目录 `build/issue273-analysis/review_geometry.py`、`other-equipment-geometry.json`。所有附加立方体均检查了旋转后的八个顶点；若八点都在轴对齐基础壳内，就能证明该立方体整体在壳内。未整体在壳内只排除这种特定情况，不能排除局部遮挡或其它部件、贴图造成的遮挡。

## 1. 优先候选：三种龙鳞甲的短腿刺

位置：三份 `*DragonScaleArmorModel.java` 的 `RightLegSpike` / `LeftLegSpike`，均为第 28 / 31 行。三种模型使用相同参数。

```java
addBox(-0.5F, 0.0F, 0.0F, 1, 3, 1)
PartPose.offsetAndRotation(0.0F, 5.0F, 0.4F, -1.4114477660878142F, 0.0F, 0.0F)
```

旋转后该刺的最前端为 `z=-2.561993`，其余坐标范围均位于腿壳范围内。因此正面露出距离为：

| 状态 | 腿壳前表面 | 刺露出距离 |
| --- | ---: | ---: |
| `d=0` 对照 | -2.000 | 0.562 |
| 当前护腿 `d=0.38` | -2.380 | 0.182 |
| 当前靴子 `d=0.45` | -2.450 | 0.112 |

露出距离分别减少约 68% 和 80%。相应尖刺 UV 区域在龙鳞甲外层、护腿层中都有非透明像素；已抽查火、冰、电各一种颜色，不能用“护腿贴图本来透明”排除此问题。穿齐护腿和靴子时，同一腿部模型都参与渲染，外侧的靴子壳还会遮住护腿模型的部分尖刺。

其余同源缩短也存在，但余量更大：

| 部件 | `d=0` 露出距离 | 当前对应装备的露出距离 |
| --- | ---: | ---: |
| `RightLegSpike2` / 左侧对应 | 1.362 | 护腿 0.982；靴子 0.912 |
| `RightLegSpike3` / 左侧对应，向侧方露出 | 1.399 | 护腿 1.019；靴子 0.949 |
| `RightShoulderSpike2` / 左侧对应，向上露出 | 1.127 | 胸甲 0.677 |
| `BackSpike3`，向后露出 | 0.967 | 胸甲 0.517 |

建议优先恢复最短腿刺的露出量；如需恢复其它刺的旧轮廓，可按各自伸出方向调整挂点。直接给所有细刺加入等量膨胀会同时改变粗细，不宜照搬龙钢板片的修法。

三种龙鳞头盔的 `HeadFront`、`Jaw` 不是整体被吞没的情形：其前端分别到 `z=-8.918`、`-7.915`，比当前头盔壳前表面仍伸出约 3.968、2.965。龙角、牙齿也保留外部几何；不能仅凭它们没有 `deformation` 就判定需要膨胀。尤其牙齿挂在面板或下颌下面时，扩大父面板可能反而盖住牙齿。

## 2. 次要候选：银甲裙片

位置：`SilverArmorModel.java:29` 的 `robeLowerBack` 和第 30 行 `robeLower`。

两片裙甲外表面为 `z=±2.5`，未同步 `deformation`。中立姿态下，相对护腿壳的前后间距由 0.5 缩为 0.12，相对靴子壳的相应间距只有 0.05。裙片挂在身体下面，随身体运动，而非分别随左右腿运动；间距变小会减少腿摆动前的几何余量。不过旧设计本来就可能在动作中相交，本次没有把它定为“新出现的整片消失”。

护腿模型的 `body` 也保留了同名裙片，但默认护腿贴图 `textures/entity/equipment/humanoid_leggings/silver.png` 对应完整 UV 矩形 `(4,55)-(22,64)` 的 162 个像素全部透明；外层贴图对应区域有 52 个非透明像素。因此默认资源下，不能将同名几何直接判成胸甲和护腿的重复裙片闪烁问题。

若继续调整，适合针对裙片保留前后余量；这是低于短腿刺的优先级。

## 3. 银甲头盔及其它装饰

- 银甲 `faceGuard`：旋转后范围为 `x=[-4.5,4.5]`、`y=[-12.900,-0.858]`、`z=[-6.646,5.315]`。中部侧面会与变厚后的 `hat` 相交，但前端仍伸出约 1.696，顶部也明显在壳外；没有龙钢面甲那种整块在壳内的问题。侧面旧坐标本就与 `d=0` 的帽壳侧面同为 `±4.5`，不宜把原先接缝直接当作稳定的外部板片。
- 银甲两侧翼、头顶冠：旋转后分别保留明显向后、向上的外部几何，未发现整件吞没。
- 死亡蠕虫甲：较短的外侧肩刺 `spineR2/spineL2` 顶部仍伸出约 0.885；头部最后一根 `spineH7` 向后仍伸出约 1.303。根部少露出了一部分，但无需按“消失部件”一律加粗。
- 巨魔甲：例如右侧主角最前端约 `z=-6.951`，当前帽壳前表面 `-4.95`，仍露出约 2.001；嵌套末段也保留外部几何。
- 海蛇甲：头鳍、臂鳍、腿鳍均有明显外部几何。臂鳍同时对照已扩大后的护肩，仍向外伸出约 3.48，不存在被本次护肩修正整体盖住的问题。
- 三种龙钢甲：本次检查也覆盖预览未改尺寸的各级龙角、冰刺等，没有发现其它附加立方体整体落入基础壳内。此前面甲、肩甲和腿片的修正仍保留在工作区。

## 4. 其它装备的路径核对

- 眼罩、耳塞、羊毛盔甲走默认装备模型及贴图，没有独立的附加板片，未发现本次这种基础壳与附加件膨胀不一致的机制。
- 26.1.2 没有独立的 `CopperArmorModel` 或它的自定义渲染注册；铜色龙鳞装备已被龙鳞模型检查覆盖。
- 龙用盔甲、骏鹰盔甲使用原实体网格重绘装备贴图，不走这里的自定义人形盔甲膨胀路径。
- 死亡蠕虫手套、潮汐三叉戟、巨魔武器等手持模型未使用这套人形外壳偏移；抽查其模型及渲染入口，未见相同的壳层膨胀失配。
- 恐惧骑士自身模型的基础身体和附加甲片都传入 `modelScale`，不属于“只膨胀基础壳”的写法。

这些路径核对只回答与 #273 相同的模型问题，不代表对其它渲染行为作了全面无缺陷保证。若后续修正，建议先处理三类龙鳞甲的短腿刺，再决定是否需要调整银甲裙片和其余装饰的根部余量。
