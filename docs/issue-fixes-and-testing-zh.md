## 行为及兼容边界

- 核心方块注册名、召唤水晶组件和龙位置表格式保持兼容。旧锻炉整数进度可读；旧版本已被 short 截断成负数的进度无法恢复，加载时归零。
- 召唤最多等待 200 个服务端 tick，使用有 220 tick 超时的临时票据。成功、失败、换手、玩家死亡/离线、换维度和停服会释放请求票据。没有持久化 `setChunkForced(true)`。自动测试覆盖成功加载、来源区块再次卸载和跨维度移动；取消/超时路径仍建议手工回归。
- 召唤只接受活着、未成尸体、已绑定且主人 UUID 匹配的相应龙种。成功后才清水晶绑定。老存档中从未建立位置索引、当前也未加载的龙，需要先加载一次其区块，才能建立可靠的新索引。
- 权杖由“松手时一次扣耐久”变为“每秒按有效目标即时扣耐久”；总成本按实际目标计算。连锁闪电修复重复入队后，不再对同一目标反复应用伤害。
- 锻炉保留供火启动、最多 40 tick 余热和无热衰减。核心 tick 内局部复用结构结果，没有引入跨 tick 的结构缓存。
- 小精灵计时每 200 tick 标记保存；产出、收取和进出等关键状态立即标记。标记 dirty 不等于每次变化强制刷盘。
- 没有量化 FPS、TPS 或 MSPT 收益。减少重复查询、解析和烘焙是代码层面的工作量改善，不能直接换算成整体性能百分比。

## 建议的手工测试方法

以下按功能组合，使用独立测试存档；需要多人显示判断的部分用两名真实客户端。它们是后续测试步骤，**本轮未执行客户端画面及双客户端回归**。

### 1. 锻炉、库存与重载

在未拼好的火/冰/雷核心中预放材料，补齐最后一块，然后反复拆装一个结构块。库存和已打开菜单应保持，地上不应弹材料；真正拆核心只掉一份。保留输入口、拆掉核心重放，装料后应重新受火。

持续供火生产若干件，再停止供火：余热耗尽后进度应下降。中途 `/save-all flush`，离开卸载区块再回来，并重启一次服务器。核对材料、产物和保存的进度。自定义组件配方可以在输出槽预放同物品不同名字的栈，确认拒绝合并。

### 2. 多人同步、菜单和正常警报

两名玩家分别在主世界和下界的相同坐标放小精灵罐/房屋/底座。一端放物品或让小精灵进出，另一维度同坐标显示应不变；同维度观察者应立即更新。用非默认颜色罐让第二名玩家首次进入区块，核对颜色和产粉状态。收粉、保存、重启后不能再次领取已收产出。

打开讲台后让另一人拆除，或传送到八格外，确认界面关闭/操作失效。生存玩家无攻击地接近鸡或村民，不应因开始跟踪直接引发守卫攻击；实际攻击仍应触发正常警报。

### 3. AI、多部件与地形

批量生成不同创建顺序的饥饿龙、受伤鸡蛇/羽蛇、小精灵和可找马的恐惧骑士，提供食物、可拾物或马。运行一两分钟，不应有一部分实体长期完全不搜索。给符合性别、年龄、发情条件的龙配对，确认仍能产蛋；羊应持续跟随活着的独眼巨人。

用偷到物品的小精灵验证能逃向远处而非立即结束；在沙地混入石头障碍，观察大蠕虫绕行。海蛇不同尺度下攻击头、身、尾部，确认服务端命中一致；移除鸟群首领后其余鸟仍能继续活动。

提高测试世界 `randomTickSpeed` 后观察设置 `revert=true` 的转化泥土、路径和沙砾恢复；沙砾仍应正常下落。结束后恢复原规则值。

### 4. 乘骑、战斗与两人权杖

分别乘骑海马、蠕虫、骏鹰、羽蛇和龙，测试上升、下降、攻击和下骑；让幼龙上肩后测试下肩。重点观察按控制键时是否发生坐标取整式跳动。

两人同时使用权杖对不同目标持续照射，再分别松手。每人只损耗自己的耐久，旁观客户端的光束应随失去目标或松手消失。用闪电武器攻击一群可见生物，检查同一次连锁不会反复命中同一目标。主手拿其他工具、副手拿幽灵剑挥动，只有副手扣耐久并有弹体；冷却内不重复生成。

### 5. 召唤加载、取消与重启

绑定自己的龙，保持其区块加载召唤一次；重新绑定后飞到远处使龙的区块卸载，再召唤。也测试龙在下界、玩家在主世界的场景。成功时应只有一条同 UUID 的龙，原所有者和装备保留，水晶解绑。服务器重启后再进行卸载召唤，验证位置索引来自磁盘。

发起卸载召唤后立即换手、切换维度或退出服务器；请求应取消，水晶不应提前解绑。绑定缺失 UUID 的测试水晶或使目标不存在，超过 200 tick 后应失败且不遗留加载请求。用 `/forceload query` 核对没有新增持久强制区块；如需检查临时票据是否释放，还应等待来源区块卸载并查看区块调试/分析工具，`forceload` 本身不展示 region ticket。

### 6. 客户端图鉴、石像与性能采样

打开有图片、物品、方块和配方的图鉴页并反复翻页，切换中文/英文；修改测试资源包的图鉴文字后 F3+T，仍在界面时应看到新内容。缺页或格式错误只应在加载该页时记录一次，不应每帧刷日志。

摆出同类型但不同 NBT 的巨魔/九头蛇石像，交换进入视野顺序，核对纹理、头数和裂纹；切换世界后再次检查。用 JFR/分配分析器在固定视角采样，确认稳定图鉴页没有持续的文本开流/解析栈，石像稳定渲染没有持续的备用 PigModel 烘焙栈。

若测性能，分别用基线和本轮 JAR、相同依赖/配置/种子/实体数量，预热后采样相同时间，记录 MSPT 分位数、帧时间与分配率。功能回归通过后再加入附加优化 JAR 单独对照，不能把附加模组改变碰撞/吐息覆盖造成的减负算成本轮修复收益。
