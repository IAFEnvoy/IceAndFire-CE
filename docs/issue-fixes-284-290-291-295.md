# Fixes for issues #284, #290, #291 and #295

Applies to the 1.20.1, 1.21.1 and 26.1.2 branches. No new dependency or configuration is required.

| Issue | Cause and change |
| --- | --- |
| [#295](https://github.com/IAFEnvoy/IceAndFire-CE/issues/295) | The 1.20.1 bird flight code dereferenced an empty flock's leader. Refresh/elect the leader before use, snapshot it once, handle an empty flock, and remove departing birds immediately. The newer branches already had null checks; they now also use one leader snapshot. |
| [#291](https://github.com/IAFEnvoy/IceAndFire-CE/issues/291) | Unridden hippogryphs accumulated upward velocity without a flight destination, then disabled flight in midair. Bound takeoff velocity, select nearby unobstructed destinations at 4–12 blocks above terrain, descend at a controlled speed, and restore gravity on touchdown. Negative Y alone no longer triggers takeoff. |
| [#290](https://github.com/IAFEnvoy/IceAndFire-CE/issues/290) | Forge selection admitted unavailable dragons and used different range/visibility rules from the breath logic. Share an awake, living adult check, matching element, tame/chain requirement, 50-block range, and a head-to-input ray. Fix the inverted chain test, compare target positions by value, and stop breathing when the target becomes invalid. |
| [#284](https://github.com/IAFEnvoy/IceAndFire-CE/issues/284) | Corpses reported alive. Return the actual death state while retaining body selection and harvesting. On the NeoForge branches, also stop picking dead dragon parts: Re-Retro Damage Indicators resolves parts to their parent without checking the parent's health. The 1.20.1 parts use a different entity implementation. |

## Automated verification

The existing loader-backed regression suite now covers an empty flock during flight; corpse death state and harvesting; hippogryph takeoff, horizontal movement, bounded height, descent and touchdown; and an assembled lightning forge with real recipe ingredients, unavailable dragons, chained dragons, obstruction and actual power transfer.

Run from each branch checkout with its required JDK:

```powershell
# 1.20.1, Java 17 (Fabric runtime; build validates Fabric and Forge)
.\gradlew.bat :fabric:runGametest --offline --console=plain
.\gradlew.bat build --offline --console=plain

# 1.21.1, Java 21
.\gradlew.bat runGameTestServer --offline --no-configuration-cache --console=plain
.\gradlew.bat build --offline --no-configuration-cache --console=plain

# 26.1.2, Java 25; the asset task also requires a discoverable Java 21 installation
.\gradlew.bat -PauditRegression runGameTestServer --offline --no-configuration-cache --console=plain
.\gradlew.bat build --offline --no-configuration-cache --console=plain
```

Regression code is excluded from normal release builds. For 26.1.2, run the final build without `-PauditRegression`.

Verified on 2026-11-13: 1.20.1 passed 30/30 tests, 1.21.1 passed 22/22, and 26.1.2 passed 31/31.
The 1.20.1 power-transfer test also exercises 32 deterministic particle random seeds.

## In-game checks

1. On an open, flat area, observe several unridden hippogryphs for at least 30 seconds. They should take off, travel locally and descend without a sudden free fall. Repeat below Y=0, then check ridden takeoff, hovering, ascent, descent and dismounting.
2. Build and fill a lightning dragonforge, position an awake tamed adult with a clear head-to-input path, and verify recipe progress. Add a sleeping dragon or baby nearby; the adult should still be selected. A wall between its head and the input should stop fueling.
3. With Re-Retro Damage Indicators installed on 1.21.1, kill a dragon and look at both its body and former wing/head hitboxes. After the HUD's configured linger interval, it should stop acquiring the corpse. Right-click the corpse to verify blood/loot/skull harvesting.

The automated tests run the real server AI, collision, raycast, forge and interaction code. The third-party HUD rendering and manual riding checks above require client-side verification.
