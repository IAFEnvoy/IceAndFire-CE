# 26.1.2 修复集中测试指南

适用 Minecraft 26.1.2 / NeoForge 26.1.2.97 / Java 25。命令在项目根目录 PowerShell 执行。修复范围及证据边界见[修复报告](fixes-26.1.2-2026-11-05.md)。

## 1. 自动回归

```powershell
.\gradlew.bat -PauditRegression runGameTestServer --console=plain
.\gradlew.bat -PauditClientRegression runClient --console=plain
.\gradlew.bat -Pissue292Regression runClient --console=plain
.\gradlew.bat -Pissue285Regression runClient --console=plain
.\gradlew.bat clean build --console=plain
```

最后一个命令用于生成普通发布产物。测试通过后仍需执行该命令清理测试构建遗留，不能分发带 opt-in 测试源码构建的 JAR。

- 第一条运行 25 项模组回归，另外包含 1 项默认测试；期望日志为 `All 26 required tests passed`。覆盖网络坐标、讲台边界、锻炉、持久化和初次同步数据、AI 调度及生命周期、部件、寻路、鸟群、地形恢复、水晶卸载召回/跨维度、权杖、闪电、副手幽灵剑、龙抓取猎物的服务端结算，以及冰中龙蛋的异常数据加载和正常数据往返。目录：`build/regression-runtime`。
- 第二条启动独立客户端，资源加载后运行五类模型的正/逆序延迟回调断言，并自行退出。期望 `IAF CLIENT REGRESSION: all 5 deferred geometry/model tests passed`，以及 `build/client-regression-runtime/client-regression-result.json` 中 `passed:5, failed:0`。该测试不进入游戏世界，不替代画面验收。
- 第三条进入独立集成世界，使用真实 `ClientLevel` 检查三种龙、两个阶段、本地与远端玩家实体共 12 组嘴部定位场景，期望 `IAF ISSUE 292 CLIENT: all 12 player-prey scenarios passed`。详情见 [#292 修复说明](issue-292.md)。
- 第四条在独立集成世界中执行 `/setblock` 放置空冰蛋，并调用生产冻结逻辑生成四种正常冰蛋；检查实际方块实体更新包及完整区块包，共 10 组场景。期望 `IAF ISSUE 285 CLIENT: all 10 ice egg network scenarios passed`。详情见 [#285 修复说明](issue-285.md)。
- 第五条期望 `BUILD SUCCESSFUL`。普通产物在 `build/libs/`，其中不应存在 `com/iafenvoy/iceandfire/regression/` 或 `data/iceandfire/structure/regression_empty.nbt`。

## 2. 集中人工验收

使用单独的 26.1.2 测试实例、必要依赖和新建创造世界。进行多人场景时，两名玩家使用相同构建。每组检查后保存、退出并重进一次，便于发现只在内存中正确的状态。

### 展示、渲染和资源重载

1. 并排放两座底座，一座放龙蛋、一座放普通物品；放冰中龙蛋、带不同颜色精灵的罐子和房屋、装有图鉴的讲台。退出区块再返回，检查内容显示；让第二名玩家首次进入该区块再核对。
2. 同屏放不同动画的两只九头蛇、两枚蛋和不同开合的蠕虫手套，九头蛇断不同头；移动相机改变绘制顺序，确认状态不互相覆盖。恐惧骑士分别穿单件和全套护甲，对照头/胸/腿/脚可见部件。
3. 对使用渲染桥的小精灵或龙施加隐形，然后叠加发光；对照普通玩家、同队能看到友方隐形的玩家。检查身体、轮廓和装备层。检查龙眼睛/护甲、古代海蛇覆盖层正常存在。
4. 放置同种但不同 NBT 的石像，如不同年龄/颜色；检查各自外观，切维度并返回后重看。
5. 翻图鉴不同章节，切换语言，再按 F3+T 重载。检查正文、图片、配方及缺翻译时的英文回退。启用内置 legacy 材质包，检查无版本格式不兼容提示和主要贴图。

### 锻炉、库存及持久化

1. 建完整锻炉，放输入和龙血，启动后拆/补结构，连续切换多次。库存不丢失、不重复掉落，核心随结构启用/禁用，输入口能重新连接替换后的核心。
2. 启动烧炼后停止龙焰，余热用完后观察进度下降；再供能恢复。输出放同物品但不同组件的物品，应拒绝错误合并。
3. 进度运行中 `/save-all flush` 后停服重启，确认库存、进度和余热能够恢复。收取精灵粉、释放精灵后也执行同样保存/重启，不能重复产粉或重复释放持物。

### 水晶与生命周期

1. 用自己的水晶分别召唤已加载龙、离开足够远使区块真正卸载的龙、重启后仍未加载的龙，以及其他维度中的龙。每次应只出现一只，成功后水晶解除绑定；他人的水晶/龙种不匹配应失败。
2. 打开卸载召回配置后发起请求，分别换掉水晶、断线、切维度；另用指向失效位置的绑定等候超时。检查请求结束后不保留 `iceandfire:dragon_summon` 票据。`/forceload query` 只反映永久强制区块，不能单独证明临时票据释放。
3. 两名玩家召回同一区块的不同龙，确认先结束的请求不会提前释放另一个请求仍需的共享票据。GameTest 已自动检查成功路径票据，这组人工测试补取消/超时/共享路径。

### 多人网络、战斗与 AI

1. 两名玩家在不同维度相同坐标各放精灵罐、房屋和底座，分别修改。另一维度不得被串改；返回原维度和重连后显示一致。
2. 正常骑乘各类坐骑，检查控制仍工作。讲台打开后走远、拆掉讲台，旧菜单不能继续学习。非法按钮和伪造坐标由自动回归覆盖，无需人工制作坏包。
3. 两人同时使用鸡蛇权杖，只应扣各自正在使用栈的耐久；目标死亡、卸载或停止使用后光束消失。用闪电武器攻击聚集生物，检查追加目标不重复；幽灵剑用副手触发，主手物品不被错误扣耐久。
4. 野生龙观察自然捕猎与繁殖，羊跟随独眼巨人，持赃物精灵逃跑；不同实体生成时刻都应能启动搜索。移除鸟群首领后应有存活成员接任；海蛇缩放后碰撞部件应仍可命中。
5. 暂停时间：`/gamerule minecraft:advance_time false`，依次 `/time set 1000`、`6000`、`13000`、`18000`。启用对应配置，使用带 `iceandfire_night_siren` 标签的未命名自然塞壬，观察日间清理和夜间保留。普通 `/summon` 默认不带自然生成标签。
6. 观察龙息转化地形随机恢复、焦化小径压实及下落方块。扩大精灵村庄采样，确认四个道路方向和六种房屋都可出现；小样本没出现某变体不能直接断言失败。

## 3. 性能对照

使用相同硬件、JVM 参数、种子、视距、实体数量、锻炉数量与相机位置，预热后重复采样基线和修复版。备份世界并分别复制为两个测试副本，避免修复版存档反过来改变基线。

服务端比较 MSPT 的 p50/p95/p99 和 JFR CPU/分配，重点看实体范围查询、闪电、鸟群及锻炉；客户端比较图鉴持续打开、密集实体及展示方块时的帧时间和 GC。记录原始样本及配置，平均 TPS 恒为 20 不足以证明性能相同。本轮没有执行这些性能测量，不能据此给出提升比例。
